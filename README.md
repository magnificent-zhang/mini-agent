# mini-agent
## 项目介绍
本项目是一个mini的agent框架，目前只实现了简单的Agent loop，后续会进一步完善整个框架的稳定性与鲁棒性。

## 功能介绍
本框架目前在起步阶段，功能相对较少，目前只有：
1. 问答时间与日期
2. 简单的加法，乘除法运算
3. 读文件，修改文件，列举文件：自己设计的简单工具，可供模型自己调用
4. 后续功能持续增加中······

## 如何运行
### python环境
本项目支持在python3.10及以上的环境运行，如果没有或者python版本低于3.10，建议去官网下载和升级。建议使用python版本管理器或着虚拟环境，避免污染环境中的python工具。
### 设置模型API
本项目原本用的模型是deepseek，但是用户可以根据自己的需求更改模型提供商。
``` python
    client = OpenAI(
        api_key = os.environ["DEEPSEEK_API_KEY"],
        base_url = "https://api.deepseek.com",
    )
```
修改的路径在根目录下的```agent.py```，建议不要直接在代码中写明文的api_key，建议把api_key写到环境变量中，base_url建议去模型官网的接入文档自行查看。
### 运行文件
运行本项目的命令如下：
``` python agent.py ```
这个命令适用Mac的虚拟python环境，如果是在Mac的全局环境，需要运行：
```python3 agent.py```

## 设计说明
- question1:Agent Loop是怎么工作的，什么时候停止？
- answer1:Agent Loop是在每一次user输入进消息队列的时候开始的，此时进入到Agent Loop中，模型根据user的信息，决定是否调用工具，如何调用工具（并行还是串行）。如果不需要调用工具，就直接退出Agent Loop，生成回复用户的信息。如果需要调用工具的话，模型就会发起调用工具的请求，然后等待工具的结果，根据结果决定是否要再调用工具还是直接回复用户。Agent Loop退出条件是，当模型不再发出调用工具的请求时，就会退出Agent Loop。
- question2:为什么文件操作限制在工作区内，safe_path 防住了什么？
- answer2:这是在框架层面就限制模型的越界行为，是安全边界很重要的一部分。因为如果只有系统prompt或者只根据用户的prompt，模型会在多伦对话后忘记这个约束，从而产生越界的行为，但是在框架层面限制就不会出现这样的问题，这也是模型要访问系统文件路径时格外需要注意的点。safe_path限制了模型访问文件系统的范围，模型只允许在workspace内工作，从代码层面实施了安全边界。
- question3:为什么写入和编辑需要人工审批，审批为什么放在 Agent Loop 里而不是工具函数里？
- answer3:因为写入和编辑本身就是对文件内容的更改，理应由人工审批后再执行。写入操作时可能会出现本身存在同名文件，但是模型又要调用工具进行覆盖的情况，这种情况就需要人工审批来抉择；编辑操作也有类似的情况，即一个文件中的内容反复出现了多次，但是模型本身不知道要编辑或者改写哪一个？如果不加人工审批的话，大胆的模型就会去猜测user的意图，从而直接修改文件，这是不允许发生的。审批是程序本身的要求，工具就单纯的是工具，而审批的工作是需要在调用工具之前就应该做的，所以不应该放到工具函数里，而放到agent loop中就可以实现在每次调用工具之前就进行审批，审批不通过，就不调用工具了，反而避免了调用工具之后才发现审批不通过的现象，减少了工具调用的情况。
- questino4:为什么要有 edit_file，而不是只用 write_file？
- answer4:有多重原因，首先就是token成本的问题，如果是write_file，那么就要把整个内容全部放到assistant的content中，这本身就是一种token的浪费，其次，后续的每次对话都会将这批内容输入给模型，造成的浪费是巨大的，如果是修改多个大文件的话，模型上下文很快就满了。然后就是截断问题，假设文件很大，但是read_file截断了一部分，write_file根据这部分只重写了截断部分的内容，后续的信息是直接丢失了的，模型根本意识不到这个问题。
